The description test is a rule about words, applied before any code exists. Describe the field without naming its system. If the description survives a stranger, the field is understood.

## The rule

One sentence, no system names, no abbreviations that only your team uses. Then read it to someone outside the project and listen for the question they ask first.

## Why it works

It removes the crutch. Most integration documentation is a mapping dressed as a definition, and a mapping cannot be wrong in an interesting way — it can only be out of date.
